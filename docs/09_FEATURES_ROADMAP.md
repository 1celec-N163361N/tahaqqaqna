# 09 — خارطة المميزات المطلوبة (14 ميزة)

> **قاعدة الاختيار:** لا ميزة لمجرد الظهور. كل ميزة تعالج (1) مشكلة حقيقية أثبتها الفحص، (2) نقطة ضعف موجودة عند فريق آخر على الأقل، (3) لها «لحظة عرض» تُثبتها أمام اللجنة في ثوانٍ.
> **الرموز:** 🔴 أساسية قبل العرض · 🟠 عالية القيمة (قبل اللجنة إن أمكن) · 🟢 بعد المسابقة/إنتاجية.

---

## المجموعة أ — منطق القرار (قلب التميّز)

### F1 — محرك الثقة التكيّفي 🔴
- **المشكلة:** المتقدم بلا بيانات حيوية سابقة — و«قبول/رفض» الثابت يبدو صندوقًا أسود.
- **الحل:** سلسلة أدلة بأوزان معلونة + مؤشر ثقة حيّ + إعادة توزيع عند سقوط دليل + قاعدة أمنية (غياب كشف التزييف ⇒ مراجعة إلزامية).
- **لماذا يميّزنا:** الفريق الوحيد الذي يحمي قراره بشرح رياضي قابل للتدقيق.
- **لحظة العرض:** «أوقف الجلسة الحيّة» → الثقة 75% + تحويل إلزامي للمراجعة.
- **الحالة:** ✅ نموذج جاهز ومُختبَر (trust_meter.html).

### F2 — لوحة المراجع البشري المصغّرة 🟠
- **المشكلة:** كل الفرق تُسأل «وش يصير لما يفشل التحقق؟» — ولا أحد عنده جواب تشغيلي.
- **الحل:** شاشة موظف: قائمة الحالات المحوّلة + الثقة + الدليل الناقص + إجراء موافقة/رفض بسبب.
- **لحظة العرض:** تحويل حالة من «مراجعة» إلى «مقبولة» أمام اللجنة بضغطة.

### F3 — كاشف التناقض بين المصادر 🟠
- **المشكلة:** تعارض تاريخ الميلاد/الاسم بين السجل المدني وشهادة الميلاد — «نعم/لا» لا تكفي.
- **الحل:** إيقاف المسار + عرض التعارض صراحة («المصدر أ يقول… المصدر ب يقول…») + تحويل للمراجعة بدرجة أثر.
- **لحظة العرض:** إدخال تاريخ ميلاد مخالف → النظام يكتشف ويشرح.

### F4 — بطاقة «لماذا رُفضت» القابلة للمشاركة 🟠
- **المشكلة:** الرفض الغامض يخلق شكاوى متكررة وإعادة تقديم عشوائية.
- **الحل:** عند الرفض: بطاقة تشرح السبب الدقيق + الإجراء التالي (مثال: «صحّح اسم الأم في السجل المدني») قابلة للمشاركة مع ولي الأمر.
- **لماذا يميّزنا:** لا فريق آخر يعالج «ما بعد الرفض».

## المجموعة ب — تجربة الاستخدام والصمود

### F5 — مساعد التصوير الذكي (Live Capture Coach) 🟠
- **المشكلة:** أكبر سبب رفض فعلي في الفحص: «ملامح الوجه غير واضحة» — والفرق تكتفي بتعليمات ثابتة.
- **الحل:** توجيه لحظي أثناء الالتقاط: «اقترب»، «أضئ»، «ثبّت» بمؤشرات مباشرة على الشاشة.
- **لحظة العرض:** إضاءة سيئة → المساعد يصححها خطوة بخطوة حتى القبول.

### F6 — فحص جاهزية الجهاز قبل البدء (Pre-flight) 🟠
- **المشكلة:** المستخدم يصل للخطوة 5 ثم يكتشف أن كاميرته/شبكته غير مناسبة — إحباط كامل.
- **الحل:** فحص قبل الرحلة: دقة الكاميرا، الإضاءة، سرعة الشبكة، المتصفح — مع «جهازك جاهز ✓» أو إصلاحات مقترحة.
- **لماذا يميّزنا:** يمنع الفشل قبل حدوثه بدل معالجته.

### F7 — وضع الانقطاع والاستئناف 🟠
- **المشكلة:** المناطق النائية/الشبكات الضعيفة تنقطع في منتصف الجلسة — والفئات المستهدفة صريحة في وثائقنا.
- **الحل:** حفظ الحالة والاستئناف من نفس الخطوة بلا إعادة نفاش، بصلاحية مؤقتة.
- **لحظة العرض:** قطع الاتصال ثم استئناف من نفس النقطة.

### F8 — وضع الوصولية البديل 🟠
- **المشكلة:** التحديات الحركية/الصوتية تستثني ذوي الإعاقة السمعية/النطقية — وهم ضمن مستهدفينا.
- **الحل:** بدائل (قراءة مكتوبة، رمش مزدوج، لمسة) بنفس وزن الثقة.
- **لحظة العرض:** تبديل الوضع أمام اللجنة وإكمال التحقق بنجاح.

### F9 — نمط المرافق (Companion Mode) 🟢
- **المشكلة:** كبار السن يحتاجون مساعدة في الرحلة — والحل الحالي يتركهم وحدهم أمام الكاميرا.
- **الحل:** مرافق موثوق يتابع نفس الجلسة على جواله لإرشاد والده/والدته — بموافقة، وبلا رؤية للبيانات الحيوية.
- **لحظة العرض:** «ساعد والدك عن بُعد» — قصة إنسانية تُذكر.

### F10 — ميزانية المحاولات الشفافة 🟢
- **المشكلة:** محاولات غير محدودة تفتح باب التجربة والخطأ للمحتالين، وضبابية للمستخدم.
- **الحل:** عدّاد محاولات مرئي + تهدئة + تحويل للمراجعة عند الاستنفاد (موجود جزئيًا: 3 محاولات).
- **لماذا يميّزنا:** يجعل مكافحة الاحتيال جزءًا من الواجهة، لا إعدادًا مخفيًا.

## المجموعة ج — الثقة المؤسسية والقيمة

### F11 — سجل قرار مُعمّى بالتدقيق (Audit Trail) 🟢
- **المشكلة:** أي قرار حكومي يحتاج «من قرر ولماذا» — PDPL والمسؤولية القانونية.
- **الحل:** سجل مقفل (Hash-chained) لكل قرار: الأدلة، الأوزان، النتيجة، المراجع — يُفحص ولا يُعدَّل.

### F12 — ختم الجلسة الحيوية (Session Seal) 🟢
- **المشكلة:** ادعاءات «الفيديو مُعاد/مزوّر» لا تُحسم بسجل عادي.
- **الحل:** توقيع رقمي للجلسة (وقت + تحديات منجزة + بصمة جهاز) يُرفق بالقرار — يثبت أن الجلسة حيّة وأصلية.

### F13 — حزمة أدلة بمشاركة آمنة (رمز/QR) 🟢
- **المشكلة:** البنوك والخدمات تعيد التحقق من كل معاملة — لا دليل محمول.
- **الحل:** رمز يُمثّل «حزمة أدلة» (نوع الدليل + تاريخه + مصدريته) بلا بيانات حيوية كشفية.
- **ملاحظة إنصاف:** الفكرة مستوحاة من فريق بصمة الأثير — نتبناها بصيغتنا (حزمة أدلة لا شهادة إصدار).

### F14 — محاكي المخاطر (Red-Team) 🟢
- **المشكلة:** «كيف تثبتون أنكم لا تُخدعون؟» — فرق ترفع ادعاءات بلا عرض.
- **الحل:** لوحة داخلية تُشغّل هجمات محاكاة (إعادة فيديو، صورة مثبتة، وكيل) وتعرض استجابة النظام.
- **لحظة العرض:** هجمة تُحبط أمام اللجنة.

## خطة التنفيذ

| المرحلة | المميزات | لماذا |
|---|---|---|
| قبل العرض مباشرة | F1 (تكامل) + F2 | قلب التميّز + إجابة سؤال الفشل |
| إن بقي وقت | F3 + F4 + F5 | منطق التعارض + ما بعد الرفض + تقليل الرفض |
| بعد التثبيت | F6 + F7 + F8 + F9 | جاهزية + صمود + عدالة + قصة إنسانية |
| إنتاجية | F10–F14 | تدقيق + إثبات + قيمة تجارية |

> **القاعدة الحاكمة:** لو اضطررنا للاختيار: F1 + F2 + F3 — يحوّلون «حلًا تقنيًا» إلى «نظام قرار» متكامل القصة.
